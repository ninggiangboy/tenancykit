# Caller surfaces: labels enforced and one document per caller

## What shipped

- `CallerLabelRules` and `CallerOpenApiSplitter` as `core-openapi` test fixtures. Every contract test checks the labels,
  applies the one-caller rule behind `singleCallerPerPath` (off until phase 6/7, per the updated plan), and
  writes/verifies `contracts/openapi/<caller>/<app>.yaml` under `-Dopenapi.update=true`.
- 31 per-caller documents across the ten apps. Billing's `billing-tenant-system.yaml` and its private filter are gone;
  `tenant-system/billing.yaml` is generated by the same splitter. The generic split carries the tenant-system
  operations but not the old hand-written title, server and per-operation apiKey scheme.
- Booking, Customer and Loyalty label their hand-written documents (labels and the "Callers / Requires" line) and
  compare both with the served document operation by operation. Their per-caller files split the hand-written
  document, so documented-ahead operations are included.
- `make docs` writes a Scalar page per caller plus a landing page from the per-caller files. `docs/audiences-and-surfaces.md`
  explains the seven callers and carries a generated matrix (app x caller x current prefix x container x operation
  count). `make docs-check` fails on a drifted matrix or a per-caller file whose label no longer names its caller; a new
  docs workflow runs it.

## Evidence

- 476 operations across the ten documents, 0 without a label, 0 `x-public`.
- Contract tests pass in all ten services; architecture tests pass in all eleven.
- `make docs-check` passes; a label edit in `tenant-user/survey.yaml` makes it exit non-zero, and restoring passes.
- `make docs` served the landing page and seven caller pages (200), and the per-caller YAML sources (200).
